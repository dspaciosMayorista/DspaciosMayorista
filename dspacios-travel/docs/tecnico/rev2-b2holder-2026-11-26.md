### Role permissions (no widening)
The card is built from the row the session already read through RLS. `cotizaciones` policies (migration 154, `cotizaciones: lectura`) allow `superadmin, gerencia, administracion, operaciones, venta` of the same tenant (superadmin both); the detail page additionally 404s on another tenant (`autorizaTenant`). The print view reads the same columns with the same client, so the card exposes nothing the print view did not. Allies/agencia/freelance have no policy on this table. There is no existing document-masking helper for quotations (the contract-side masking is for `ventas_basica`/`contrato_pasajeros`, which this page does not read), so the list masks and the detail shows the full document, exactly like «Ver / Imprimir». Verified on a real database for all five internal roles, another agency and an ally (§5).

## 2. When is the holder saved to the CRM (verified in code, with corrections to the coordinator's mapping)
Two different stores:

1. **Personas de cotización** (`cotizacion_participantes` + personas/capturas; CRM module «Personas de cotización»). Written by `altaPersonasCotizacion` → RPC `registrar_personas_cotizacion`, **at quotation creation** (and again, idempotently, by retry paths) — never at view/accept/discard/convert:
   - dynamic/manual `manual-actions.ts:136`; comparative mother and child `:512`, `:574`; dynamic package `din-actions.ts:172` (visitor too: provisional capture, migration 308); Reservar `reservar/actions.ts:1675` (and after valuing a hotel request `:1735`); checkout carrito `app/tarifario/checkout/actions.ts:1481`, comparative carrito `:2180/:2327`, hotel request `app/tarifario/solicitudHotelActions.ts:203` (+ repair on repeat `:184`); «Reintentar» button on the detail page (`[id]/page.tsx` `reintentarPersonas`) while the quotation is `abierta`/`pendiente_tarifa`.
   - Only an **identified** row (document, names or surnames non-empty; `lib/personas/cotizacion.ts`) creates a seat; a traveller count never does. A failure never blocks the quotation: it logs a code and the page shows the persistent «Reintentar» notice (computed by `personasPendientes`, not a manual flag).
   - Editing the holder of an open manual quotation (`TitularEditor` → `actualizar_titular_cotizacion`) updates the seat (compare-and-set).
   - No migration/update deactivates seats on convert or discard (grep of migrations 219/308: no `update … activo`), so a converted/discarded quotation keeps its seats.
2. **`crm_contactos`** (campaign contact list, category cliente final) — an *auxiliary* effect, **correction to the earlier mapping: it is not only for the public channel**:
   - checkout carrito `checkout/actions.ts:1628` — for **every** carrito checkout (public visitor, logged-in ally, assisted sale; the origin text differs: `origenContactoTarifario`);
   - hotel request `solicitudHotelActions.ts:214` — on creation of a *new* request, public or logged-in;
   - dynamic package `din-actions.ts:164` — **only** `canal === "publico"`.
   - Not written by: manual/dynamic quotations created by staff, Reservar, comparatives, conversion, discard. A unique-index collision (23505: same document, e-mail or phone already a contact) is ignored without overwriting; any other error logs only its code; it never blocks the quotation. `datosContactoTarifario` returns null (no row) without a name.
3. **Conversion** (`convertirCotizacion` / manual / carrito) writes neither of the above; contract passengers follow the contract identity path, and «Clientes de contratos» reads `ventas` (no registration). Discard writes nothing and deletes no persons.

The UI note states only what is data-backed: the registry line from the real seats (service-role read already present in the page for the «Reintentar» logic) and a static `<details>` with the rule. It does **not** claim a `crm_contactos` row exists (that table is not read here and the insert is best-effort).

No automatic CRM creation, deduplication or reassignment was added.
