## 13. NETO base (owner rule applied, 2026-11-25) and referral payouts (still a proposal)

### 13.1 The rule the owner confirmed, and how it is implemented
**The referral uses EXACTLY the same commissionable base used to calculate the agency/freelance commission.** For NETO, it is the **original** commissionable base on which the ally commission was calculated before deducting it to obtain NETO. The referral's configured 1 % or 2 % is applied to that base. It is **not** calculated from the NETO collected or from the ally commission amount.
- **Authoritative saved value:** the base is read from the ally's commission row in `aliados_b2b` (`base_comision`/`base_explicita`/`precio_venta`) with the literal expression of `comision_b2b_total` (migration 205), now `f341_priv.base_aliado`. For a NETO sale the reservation flow writes that row «descontada en el precio» with the original gross price and the original base (`registrar_comision_b2b_reserva`, 205:419-441), so the original base survives the NETO price reduction. Legacy rows (flag `base_explicita` NULL) follow the same fallback the ally commission uses.
- **Nothing is recomputed:** the listing no longer derives a base from `ventas.precio_venta − impuesto` (which in NETO would be the discounted price) and never reads `ventas.comision_b2b` (the discount amount). If the ally's saved base is later corrected by hand, the referral follows it, exactly as the ally commission does (no payout exists yet to freeze).
- **Which row:** the rows of THAT contract and agency whose saved `aliado_id` EQUALS the attributed ally (C76-1: a row with `aliado_id` NULL is NOT evidence — e.g. a manual commission whose beneficiary is free text — and ownership is never inferred from name, contract, row uniqueness or equal amounts; such legacy rows stay unresolved, `sin_evidencia_base`, until someone links them to the ally; nothing is rewritten); a second B2B row in a NETO contract (a manual revision) is ignored — only the row born «descontada» counts; recobro-only rows (198/267) are not the ordinary base.
- **Missing evidence is reported, never guessed and never a calculated zero:** no commission row for the contract/ally → state `sin_evidencia_base`, base and amount **NULL** («Falta la base de la comisión del aliado» / «Sin evidencia» in the CRM, excluded from the totals); several ordinary rows with different bases → `base_ambigua`, amount NULL. A **0** only appears when the saved base IS 0 (`sin_base`) or the contract is cancelled. The old state `no_aplica_neto` («NETO · pendiente de decisión») no longer exists; a NETO contract carries a `neto` flag and is labelled «NETO · base original».
- **Payable only when 100 % paid** (unchanged): the same `contratos_pagados_completos` criterion (307), measured on what the buyer must pay — for NETO the total exigible, not the original PVP. This does **not** authorise payouts: no payment table, no ledger entry, no retention, nothing automatic.
- **Existing contracts:** nothing is rewritten; existing attributions keep their snapshot (referrer + %), and the base is read live from the saved ally row.
