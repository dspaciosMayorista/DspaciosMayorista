## 6. Owner questions / decisions still open (not silently decided)

1. **Destination required server-side** for all new manual quotations/comparatives/dynamic contracts (negotiated-tarifario contracts exempt). Confirm there is no legitimate destination outside the catalog (otherwise it must be added to Producto → Destinos first).
2. **Multi-destination trips**: the trip has one destination; a catalog hotel from another destination is rejected. A multi-city itinerary needs the extra hotels typed as «Hotel manual» or a per-row destination (not built).
3. **Purchase source only for hotels.** Other services (traslado, asistencia, aéreo…) keep «proveedor, o la plataforma si no hay proveedor». Extend the selector to them? (the conversion SQL would still not need to change).
4. **Direct purchase with a supplier different from the catalog's** is accepted with a notice. Should it be blocked instead?
5. **Adults must equal rooms × pax_tarifa** (exactly the booking rule). A trip with children occupying an «adult» slot in a room is not modelled (same as booking from the tarifario).
6. **Same-day return (0 nights)** is still accepted (services-only quotations). Reject for any quotation containing a hotel?
7. Editing services of an already-saved quotation (`ServiciosCotizacionEditor`) does not carry `compra`/`habitaciones`/`catalogoId` (it rebuilds rows from the saved service columns, as it already did for `catalogoId`): purchase source and rooms are validated at creation only.
