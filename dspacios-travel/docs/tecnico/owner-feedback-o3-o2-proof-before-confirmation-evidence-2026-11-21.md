## 0. Business choice taken (smallest option, flagged for the owner)

The owner asked that authorized staff see the ally's proof **before** confirming the payment. A proof has nowhere to live before a contract exists, so evidence is attached to the **quotation** (the object the ally already owns and the one the staff review before converting). Decisions that are mine and need the owner's eye:

* Up to **5 vigentes** files per quotation, PDF/JPG/PNG, 4 MB cap per file (the existing Server Action cap), content validated by magic bytes. Retiring keeps the row and the file (nothing is ever deleted).
* The evidence stays on the quotation and is shown **read-only** on the quotation page and on the contract page (above the tabs, before the abono form). It is **not** copied into `contrato_soportes_pago` (that table limits supports to the number of registered payments by design, #86), so no payment, abono or support row is ever created from an upload.
* Visibility: superadmin, and gerencia/administración/operaciones of the quotation's agency (the roles that can register payments). `venta` does not see the evidence (they do not register payments); they do receive the ally's passengers (they can convert).
* Passengers: optional, **names required, everything else optional**, at most *travelers − 1* (the titular is already captured at checkout). Stored apart (`cotizacion_pasajeros_aliado`), not inside `cotizaciones.payload`.

Signed URLs are issued only on click (2 min). No image transformations, no AI tokens, no external fees, no new cron, no new background job. Database size: two small tables.
* **Build:** one local production build (the only one for this delivery).
* **Unknown / not measured:** server-side function duration and memory on Vercel, Supabase request logs (the local PostgREST log does not record requests), cost of storage growth.
