## RC-1 — stopping by port (P1)

**Root cause.** `revision.mjs` `detenerPorPuerto()` killed whatever listened on the app/simulator port (`taskkill /T /F`), and `pila_consolidada.sh bajar` did the same for the gateway port and the code-template port 19095 (`Stop-Process` on the listener). A foreign process that took the port after the owned one ended would have been killed.

**Fix (delta).**
- New `supabase/scripts/revision_consolidada/procesos_propios.mjs`: every process the review starts is launched detached and **registered** (`*.proceso.json`: owner tag, PID, exact Windows start time via CIM, exact command line, port). `detenerPropio()` kills only when PID **and** start time **and** command line still equal the record. Verdicts: `detenido`, `ausente` (no record), `obsoleto` (process already gone), `reutilizado` (same PID, other start time), `otra-linea` (same PID and start, other command), `no-detenido`. A stale/foreign/reused record is removed and **nothing is killed**; a still-occupied port is only reported.
- `revision.mjs`: `iniciarApp`/`iniciarSim` use `lanzarPropio`; `detener` and `restaurar` call `detenerProcesos` (record-based). `iniciar` now also refuses an occupied simulator port. `restaurar` still requires `--confirmar` (unchanged).
- `pila_consolidada.sh` (gateway, template server) uses the same CLI (`lanzar` / `detener`); the inline `node -e` template server became `servidor_plantilla.mjs` so its command line is stable and verifiable. A Windows-style `AQUIW` path is passed because `MSYS_NO_PATHCONV=1` leaves `/c/...` unresolvable for native node (found when the first start failed with MODULE_NOT_FOUND; fixed before any data was touched).
- No `taskkill`/`Stop-Process` by port remains in the review tooling (grep-verified).

**Evidence.** `prueba_procesos_propios.mjs` (8 real-process checks, the unsafe stop is never executed): pure verdict function; genuine start and stop (process stopped, port freed, record removed); foreign listener without a record; stale record whose port was re-taken by a foreign process (record cleaned, foreign alive); PID reuse (other start time); same start but other command line; ownerless/corrupt record; control — only the owned process dies while a foreign neighbour on another port survives. Mutation control: removing the start-time comparison makes the PID-reuse case fail. Real lifecycle through the new tooling: `ensayo-iniciar` started app, simulator, gateway and template server with records; `ensayo-detener` stopped them by record (app and simulator reported `detenido`, ports released) — twice.

## RC-2 — outbound-only edit dropped the saved legacy return (P1)

**Root cause.** The operational flight editor (RPC `guardar_tramos_contrato`) writes only the modern columns (`numero_vuelo`, `hora_salida`, `hora_llegada`, `direccion`…) and never touches `vuelo_regreso`, `fecha_regreso`, `hora_salida_reg`, `hora_llegada_reg`. Three readers decided «legacy double row» only while the modern fields were empty, so after an outbound edit the saved return stopped being rendered: `lib/voucher/vuelo.ts` (`tramosDeFila`), `components/contrato/ContratoDocumento.tsx` and `lib/portal/vuelosContrato.ts` (`expandirTramos`). The stored data was never lost — presentation was.

**Fix (delta, application code — hence the rebuild).** The saved return columns are now rendered whether or not the outbound has been edited (return derives origin/destination from the row, as before). No migration, no data rewrite, no editor change: service association, row id, voucher key/link and the stale-state fingerprint behave exactly as before (the fingerprint already covers the whole row, so an unchanged save flags nothing).
- `lib/voucher/vuelo.ts`, `components/contrato/ContratoDocumento.tsx`, `lib/portal/vuelosContrato.ts`.
- Tests: `pruebas/voucherVuelo18.test.ts` (+2: unchanged save and outbound-only edit; issued itinerary `[LG100, LG200]` → `[LG111, LG200]`; negative control that a modern row invents no return), `pruebas/portalVuelos85.test.ts` (+1), new `pruebas/contratoDocumentoRegresoHeredado.react.ts` (+3, script `test:react:rc2` added to `package.json` and `test:react:all`). Mutation controls: removing the return from `tramosDeFila` fails 2 tests; forcing `regresoHeredadoSolo = false` fails the document test.
- Guide step **B1-13** rewritten to prove it through the real editor → server action → database → regenerated voucher: guard the unchanged save (row id, service, every legacy column identical; voucher stays valid; «sin cambios»), then edit only the outbound (legacy return columns still intact; voucher marked «Desactualizado»; regenerated in the same link and same service; **LG200 with its date and hours is still there and ordered after LG111**; no manual re-entry). Before the rebuild this step reproduced the defect on the audited build (DB assertions passed, voucher assertion failed) — kept as the pre-fix record in `…/ensayo/rc_explora`.

Limit (not changed): the editor still shows only the modern fields, so the saved legacy return is not visible *inside the editor card* (it is preserved and shown in the voucher/contract/portal). Showing it in the editor would need the editor view to expose the legacy columns (a migration); not done.
