## Findings relevant to FIX-DOCS / the lead (from G4, persisted data)

1. **Cart path (`crearSolicitudReserva` → `convertirCotizacionCarrito`) seals per-class summary rows**: `contrato_resumen_precios.resumen` for the C-0005-shaped NETO contract holds `unidades[0].grupos` = adults ×2 @ 65.880.000 centavos (658.800 NETO = 732.000 × 0,9), **`nino` ×1 @ 0**, **`nino2` ×1 @ 26.370.000** (263.700 = 293.000 × 0,9), total 158.130.000 centavos = 1.581.300; each group carries `cupos` ids and `tarifaExactaCentavos`. This is reliable per-child attribution for cart-path documents (PVP and NETO). The stored items of the same contract keep the PVP lines (Σ = 1.757.000) plus the signed line `−366.000` (`adultos:1`, description naming «hab. 1: niño de 8 años (Niño 1)»), while `precio_venta` is the exigible 1.581.300.
2. **Reservar path (`crearCotizacion` + `convertirCotizacion`) seals nothing per child**: for the DTM-0003-shaped contract `contrato_resumen_precios` is **null** and the quotation `payload` holds only the request input (no `condonado`/`beneficio` key); the quotation `detalle` and the contract items are the same four rows including the signed line. Per-child attribution there can only come from the signed line's text (room, age, class per child) and its single total amount: fully-free children are attributable (amount = n × the class tariff), but **several children with a partial benefit have no recoverable per-child split** — an honest group presentation (not a negative row, not an invented split) is the only correct rendering for those historical shapes. The owner's DTM-0003/0004 and quotations C-0003…C-0005 are Reservar-path data.
