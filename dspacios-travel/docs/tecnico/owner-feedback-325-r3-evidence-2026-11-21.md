## 1. What was wrong, reproduced

The ordinary conversion screen (`CotizacionAcciones`) preloaded ally-entered passengers, including an infant, but had no responsible-adult selector and never set `responsableIndex`, so an infant could not be converted even if staff knew the guardian. A second, hidden defect surfaced while proving it: in this path the infant-without-guardian rule was enforced **only by the database, after the contract number was consumed** — the failed attempt was reverted (no contract left) but **burned a consecutive**. Retained pre-fix evidence (`evidence-325-r3/pre-fix-numbering-gap.txt` and `journey-pre-fix-WXY-47ok.log`): contracts `DTM-0006`, `DTM-0007`, `DTM-0009`, sequence `contrato_seq_mayorista` at 9, **no `DTM-0008`**, no freed-number row. (The cart path already prevalidates the guardian before numbering, which is why the round-2 cart journey showed no gap.)

## 2. Fix (reuses the existing explicit guardian rules; nothing guessed, database validation untouched)

* `CotizacionAcciones.tsx` receives `fechaReferencia` (the departure date the server and the database use: `cotizaciones.fecha_salida`, falling back to `payload.fechaIda`) and, for each passenger classified as infant by `esInfantePorEdad(fechaNacimiento, fechaReferencia)`, renders the same **«Adulto responsable *»** selector as the staff Reservar form and the cart conversion. Options = other passengers whose age on the departure date is ≥ 18 (`EDAD_ADULTO_RESPONSABLE`, the same constant) — a passenger without a birth date is not eligible, a minor is not, the infant is never offered as his own guardian. The default is **«Sin vincular (se rechazará al generar)»**: neither the ally list nor the system selects a guardian. A birth-date change goes through the shared `recalcularVinculosPorEdad`, so a link that stops being valid is cleared instead of staying alive and invisible. A visible age/class label per row («Adulto · 41a», «Niño · 8a», «Infante · 1a») is shown as in the cart.
* No client-side bypass of the rule: a missing guardian is **sent as-is and refused by the server**, the refusal is shown, nothing navigates.
* `reservarDesdeTarifarioInterno` (shared by ordinary conversion, staff Reservar and B2B reservation): **before** requesting a consecutive it now runs the **same prevalidation the cart conversion uses** (`prevalidarResponsablesDeGrupo` / `mensajePrevalidacionGrupo`: infant without guardian, self-reference, non-existent index, minor/infant guardian), with the same reference date later used to classify (`meta.fecha_ida`) and only when there are passengers and a date (the same condition under which `esInfanteReal` can be true). It is a prevalidation only: the table trigger / atomic passenger function remain the authority and are not relaxed.
* Preserved: children-only conversions, the cart conversion, the capture panel, the restriction messages (F4722/F4723) — re-run below.
